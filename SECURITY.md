# Security policy

**English** · [Español](#es)

## Supported versions

Security fixes target the latest stable release published in [GitHub Releases](https://github.com/Tykillita/isTargetSleeping/releases).
Older versions are not maintained separately. If possible, check whether the issue still occurs in the latest
stable release; reports affecting older versions are still welcome when an upgrade or reproduction is not possible.

## Report a vulnerability privately

Use [GitHub's private vulnerability reporting form](https://github.com/Tykillita/isTargetSleeping/security/advisories/new).
Do not put vulnerability details or exploits in public issues or pull requests before coordinated disclosure.
For ordinary bugs and feature requests, use [GitHub Issues](https://github.com/Tykillita/isTargetSleeping/issues).

Include the affected app version, Windows version and architecture; the affected component; steps to reproduce
or a minimal proof of concept; expected and observed behavior; and the potential impact. Note whether the issue
requires administrator rights or an installed memory agent. Share relevant logs only after removing secrets
and unrelated personal information. Do not include real credentials or data belonging to other people.

Reports are reviewed on a best-effort basis, without a guaranteed response or fix deadline. Use the private
report to coordinate additional information, fixes and public disclosure with the maintainers. Keep sensitive
details private until a fix or another disclosure date has been agreed.

# Política de seguridad

[English](#security-policy) · **Español**

## Versiones atendidas

Los arreglos de seguridad se dirigen a la última versión estable publicada en
[GitHub Releases](https://github.com/Tykillita/isTargetSleeping/releases). Las versiones anteriores no se mantienen
por separado. Si puedes, comprueba si el problema persiste en la última versión estable; también se aceptan
reportes de versiones antiguas cuando no sea posible actualizar o reproducirlo.

## Reportar una vulnerabilidad en privado

Usa el [formulario privado de vulnerabilidades de GitHub](https://github.com/Tykillita/isTargetSleeping/security/advisories/new).
No publiques detalles de vulnerabilidades o exploits en issues o propuestas de cambios antes de coordinar su
divulgación. Para fallos comunes y sugerencias, usa [GitHub Issues](https://github.com/Tykillita/isTargetSleeping/issues).

Incluye la versión de la app, de Windows y la arquitectura; el componente afectado; pasos para reproducirlo o
una prueba de concepto mínima; el comportamiento esperado y observado; y el impacto posible. Indica si requiere
permisos de administrador o tener instalado el agente de memoria. Comparte registros relevantes después de
eliminar secretos y datos personales ajenos al problema. No incluyas credenciales reales ni datos de otras personas.

Los reportes se revisan según la disponibilidad, sin garantizar plazos de respuesta o solución. Usa el reporte
privado para coordinar información adicional, correcciones y divulgación con quienes mantienen el proyecto.
Conserva los detalles sensibles en privado hasta acordar un arreglo u otra fecha de divulgación.
